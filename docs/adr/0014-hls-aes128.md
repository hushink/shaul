# HLS AES-128 解密

## Context

HLS 一期把 AES-128 拒绝在范围之外。AES-128 是最常见的 HLS 加密方式，而且
`#EXT-X-KEY` 可以在播放列表中多次出现：密钥可以轮换，也可以在部分分片之前
切回 `METHOD=NONE`。IV 可以显式给出，也可以按分片的 media sequence number
推导。密钥属于凭据，不能写入任务 sidecar，也不能进入日志。

## Decision

- 播放列表模型：
  - `Segment` 携带 `Option<Key>`；`Key` 包含解析后的 URI 和可选 16 字节 IV。
  - `#EXT-X-KEY` 作用于其后的分片和 `#EXT-X-MAP`；`METHOD=NONE` 清除当前
    密钥，但不会把已经加密的分片当成明文。
  - `KEYFORMAT` 必须是 `identity`；`SAMPLE-AES`、其他方法或非 identity
    KEYFORMAT 记录为 `Encryption::Other`，由 `validate_media` 拒绝。
  - IV 必须是 `0x` + 32 位十六进制；缺省时用该分片的 media sequence
    number 作为 128 位大端 IV。
  - `#EXT-X-MEDIA-SEQUENCE` 必须出现在第一个分片之前；每个分片保存自己的
    sequence。
  - 加密的 `#EXT-X-MAP` 必须带显式 IV；否则拒绝，避免猜测初始化段的 IV。
- 后端：
  - 每个运行周期按 URI 去重，通过 `HlsClient::fetch_key` 获取 16 字节密钥；
    响应上限 1 KiB。密钥只驻留内存，不写入 sidecar、不进入事件或日志。
  - 密钥请求沿用 playlist/分片的跨源策略：跨源默认剥离敏感头和 `Auth`，
    除非 `allow_cross_origin_auth`。
  - 加密分片先下载为 `segment-XXXXX.enc`，解密后写成
    `segment-XXXXX.bin`；只有 `.bin` 参与续传扫描、进度统计和拼接。
  - 如果进程在下载完成和解密之间中断，下次运行会先尝试解密已有的 `.enc`；
    解密失败（例如密钥不匹配）时删除 `.enc` 并重新下载。
  - 解密使用 AES-128-CBC + PKCS7（RustCrypto `aes` / `cbc`），每个分片
    独立去填充。
- 依赖：`aes = "0.8"`、`cbc = "0.1"`，只在 `hls` feature 下引入；
  `shaul-core` 不感知 AES 或 HLS。

## Consequences

- 支持密钥轮换、显式 IV 和按 media sequence 推导的 IV。
- SAMPLE-AES、`#EXT-X-BYTERANGE`、直播、DASH、交替音轨和 ffmpeg 转封装仍
  不在范围内。
- 解密在内存中按分片进行；临时目录会同时存在 `.enc` 和 `.bin`，成功后删除
  `.enc`。解密后的 `.bin` 是明文，取消/失败时会保留在临时目录用于续传；成功
  完成后删除。需要静态加密的用户应把下载目录放在加密卷上。
- 密钥请求是额外的 HTTP 请求，但通常每个播放列表只有一到两个不同 URI。
